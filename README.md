# 课后作业 · 流水灯（STM32F103C8T6）

> 作业要求：通过面包板将**至少 4 个 LED 灯珠**与最小系统板 GPIO 连接，用软件实现流水灯效果；
> 进阶：通过 GPIO 输入检测按键触发，控制流水灯改变流向。

| 项 | 内容 |
|---|---|
| 平台 | STM32F103C8T6 最小系统板（江协 29 项套件） |
| 工具链 | Keil µVision 5.43.1 + AC6 (armclang 6.24) |
| 编译结果 | **0 Error(s), 0 Warning(s)**，Code=1980 / RO=296 / RW=4 / ZI=1664 字节 |
| 依赖 | 纯寄存器操作，**不依赖 HAL 库**（与 `01-点灯` 工程同风格） |

## 一、接线（面包板）

### 1.1 LED（4 颗）—— 共阳接法，低电平点亮

```
  3.3V ──┬──[1K]──┬──▶|──  PB12   (LED1)
         │        │     LED 阴极(短脚)
         │        └──[1K]──┬──▶|──  PB13   (LED2)
         │                  │
         │        └──[1K]──┬──▶|──  PB14   (LED3)
         │                  │
         └─────────[1K]────┴──▶|──  PB15   (LED4)
                               LED 阴极(短脚)
```

- **电阻（1K）串在 LED 阳极侧**，每个 LED 一个，共 4 个。限流 3.3V → (3.3-2.0)/1K ≈ 1.3mA，肉眼清晰可见且不伤 LED。
- 面包板**中央凹槽**两侧不连通，3.3V 和 GND 各自用一根跳线把左右两半的电源轨连起来。
- LED 有极性：**长脚=阳极**接电阻，**短脚=阴极**接 GPIO。插反不亮。

### 1.2 按键（1 个）

```
  PB0 ──── 按键一端
  GND ──── 按键另一端
```

- PB0 配了**内部上拉**，空闲读高(1)，按下接地读低(0)。
- 面包板上 GND 轨与 3.3V 轨在同一侧（通常），接按键时注意别把 3.3V 轨也短接。

### 1.3 ST-Link（烧录用）

| ST-Link | 目标板 |
|---|---|
| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND **必接** |
| RST | NRST（建议接，不接也能烧） |
| 3.3V | 目标板 3.3V（**仅作电平参考，不要用它给板子供电**） |

- **共地是必须的**，不接 GND 会连不上或烧出乱码。
- **带电插拔会变砖**，务必先断电再接线。
- 目标板自己 USB/5V 供电，ST-Link 的 3.3V 别和它打架。

## 二、引脚分配（为什么这么选）

| 功能 | 引脚 | 备注 |
|---|---|---|
| LED1 ~ LED4 | **PB12 / PB13 / PB14 / PB15** | 输出，低电平点亮 |
| 按键 K1 | **PB0** | 输入，内部上拉，按下读 0 |

**避开了这些已占用的引脚**（这是选 PB 组的原因）：

| 引脚 | 已被谁占用 |
|---|---|
| PA1 / PA2 | 板载 LED（低电平点亮） |
| PB1 / PB11 | 板载按键（按下读 0） |
| PA13 / PA14 | SWD 调试口（占了就没法烧录） |
| PA9 / PA10 | 串口 TX/RX |
| PA4 ~ PA7 | SPI1 |
| PA0 | 编码器 / TIM2 PWM（江协例程） |
| PC13 | 板载灯（备份域，最大 2mA 灌电流，不能做 PWM/串口） |
| PB3 / PB4 | JTAG 口 |

> 换引脚很容易：改 `main.c` 顶部的 `s_led[]` 表和 `KEY_PIN` 即可，其余代码不涉及具体引脚。
> 但**一定要避开上表里的引脚**，尤其 PA13/PA14（烧不了录）和板载 LED/按键（会打架）。

## 三、程序做了什么

### 3.1 上电自检
上电后 4 颗 LED 依次点亮一圈（每颗 150ms），用来**确认接线正确**。
如果自检阶段就有一两颗不亮 → 是那根线或那颗 LED 的问题，跟程序无关。

### 3.2 流水灯
LED 从 PB12 依次流到 PB15，首尾相接循环，节拍默认 150ms。

### 3.3 进阶：按键换向

| 操作 | 效果 |
|---|---|
| **短按**（松开时判定） | 流水方向反转 |
| **长按**（按住 1.5s） | 切换速度：慢 300ms → 中 150ms → 快 60ms → 慢…… |

### 3.4 技术要点

- **SysTick 1ms 中断做时基**，不是忙等延时。所以按键响应不受流水节拍影响 —— 改速度时按键依然跟手。
- `SysTick->LOAD` 用 `SystemCoreClock / 1000` 算，**万一晶振没起振（退化成 HSI 8MHz）延时不会偏差 9 倍**。
- **GPIO 写 BSRR / BRR**，原子置位/复位。不用「读 ODR → 改 → 写回」，避免读-改-写竞争。
- 按键**软件消抖 20ms**，长按判定 1.5s。
- 方向切换用 `int8_t dir` + 模运算，反向时索引回绕不会越界。

## 四、编译

### 图形界面
用 Keil µVision 打开 `water_led.uvprojx` → F7 编译 → F8 下载。

### 命令行
```powershell
D:\keil5\UV4\UV4.exe -b D:\RM\STM32\02-流水灯\water_led.uvprojx -o D:\RM\STM32\02-流水灯\build.log
```

### ⚠️ 两个必须知道的坑

**坑 1：uvprojx 不能带 BOM。**
用 PowerShell 改 XML 时，`Set-Content -Encoding UTF8`（PS 5.1）会写入 `EF BB BF`，Keil 解析带 BOM 的工程文件会**直接卡死不编译**（无日志、进程挂起）。
正确写法：
```powershell
$enc = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($f, $t, $enc)
```
用 VS Code 改也要确认右下角编码是 **UTF-8（无 BOM）**。

**坑 2：没有 `GPIO_Pin_x` 宏。**
本工程只带 CMSIS 头文件，**没有标准外设库**，所以 `GPIO_Pin_12` / `GPIO_Pin_0` 全部未定义。
本工程用自定义的 `PIN_MASK(n)` 宏代替（见 `main.c` 顶部）。
如果改用 HAL 库工程，则要用 `GPIO_Pin_12` 写法。

## 五、烧录

1. 接好 ST-Link（**SWDIO→PA13，SWCLK→PA14，GND→GND 必接**）
2. Keil 里 `Options for Target → Debug → ST-Link Debugger`
3. `Utilities → Settings → Flash Download → 确认有 `STM32F10x_128.FLM``
4. 按 **F8**（Download）

连不上的排查顺序：
1. GND 到底接了没？→ 最常见原因
2. SWDIO/SWCLK 接反了？
3. `Debug → Settings → SWD` 把频率降到 **100kHz**（面包板接触电阻大）
4. 芯片被读保护了 → 用 ST-Link Utility 解锁

## 六、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 编译卡死、无日志 | uvprojx 带了 BOM | 见坑 1 |
| `use of undeclared identifier 'GPIO_Pin_12'` | 没有标准外设库 | 用 `PIN_MASK(12)` |
| 一颗都不亮 | LED 极性反了 / 电阻没串 | 用万用表二极管档量 |
| 只有一颗亮 | 其余接线松了 | 检查面包板轨是否连通 |
| 亮但很暗 | 电阻太大 / 供电不足 | 换成 220Ω~1K |
| 按键没反应 | 按键没接地 / 接错引脚 | 万用表量通断 |
| 灯不流水但自检正常 | 速度太快看不出来 | 先设 300ms 慢速 |
| 板子不亮、下载失败 | SWD 口被占用 | 检查是否接了 PA13/PA14 给别的用途 |
